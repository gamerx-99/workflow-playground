# Roadmap — Workflow Automation Lab

> อัปเดตล่าสุด: 2026-10-21

เป้าหมาย: พัฒนาจากแบบฝึกหัด 5 ด่าน ให้เป็นแอปที่เป็นทั้ง **ที่ฝึก** และ **ที่ออกแบบ** ระบบ Automation ในตัว มีโจทย์หลายรูปแบบ มีแบบทดสอบจำนวนมาก และหน้าใช้งานที่ดี

| เฟส | หัวข้อ | สถานะ |

## Phase 2 — หลายรูปแบบ (ข้อ 1)

**รูปแบบโจทย์** — เพิ่มฟิลด์ `mode` ใน level
- [x] `build` — ต่อ flow เองตั้งแต่ต้น (ด่าน 1–4)
- [x] `fill` — flow ต่อไว้แล้ว ให้เติมตัวแปรในช่องที่เว้นไว้ (ด่าน 6)
- [x] `debug` — flow ต่อไว้ผิด ให้หาจุดผิดและแก้ (ด่าน 7)
- [ ] `order` — มีบล็อกให้ครบ ให้ต่อสายเรียงลำดับให้ถูก
- [x] `predict` — ดู flow + ข้อมูลตัวอย่าง แล้วทายผลลัพธ์ปลายทาง (ด่าน 8) — เฉลยคำนวณจากตัวจำลอง
- [x] `sandbox` — อิสระ ตรวจเฉพาะกฎทั่วไป (ด่าน 5)

**จำลองการทำงาน (▶ Run)**
- [x] ใส่ข้อมูลตัวอย่าง (sample payload) ให้ Trigger แต่ละชนิด (เลือกชุดข้อมูลได้)
- [x] ไล่รันตามเส้นเชื่อม แทนค่า `{{ตัวแปร}}` จริง และเลือกสาย IF/Switch/Loop ตามเงื่อนไข
- [x] แสดงค่าตัวแปรที่ไหลผ่านแต่ละบล็อก + ไฮไลต์ลำดับบนบล็อก/เส้นเชื่อมบนกระดาน
- [x] วางตรรกะจำลองไว้ใน `shared/simulator.js` (ไม่แตะ DOM) + ชุดทดสอบ `tests/levels.test.js` (รัน `node tests/levels.test.js`)
- [ ] AI ในตัวจำลองเป็นกฎง่ายๆ (คำว่า ด่วน/ช่วยด้วย ฯลฯ) ไม่ได้เรียก LLM จริง

**รวมเครื่องมือ**
- ~~รวม Network Topology / BOQ~~ — ตัดออก: แยกไปเป็นโปรเจกต์ใหม่แล้ว (คนละแนวทางกับ Workflow Automation)
- [ ] ยังคงแยก engine กระดาน (วางบล็อก ลากสาย ซูม) ให้ใช้ซ้ำได้ เผื่อโปรเจกต์อื่นหยิบไปใช้

## Phase 3 — แบบทดสอบมากขึ้น (ข้อ 2)

30 ด่าน แบ่งเป็น 5 สาย (track) — ไฟล์ด่านอยู่ใน `shared/levels/`

| สาย | ด่าน (id) | เนื้อหา |
|---|---|---|
| 🧱 พื้นฐานตัวแปร | 6 (1, 9–13) | Trigger → Action, ตัวแปรจากบล็อกกลางทาง ({{event_link}}, {{row_number}}), เติมช่องว่าง |
| 🔀 เงื่อนไข | 7 (2, 14–17, 7, 8) | IF, Contains, Switch 3 สาย, หาจุดผิด, ทายผล |
| 📊 ข้อมูล & Loop | 6 (3, 18–22) | Loop, Formatter, Sheets read, HTTP GET, Loop สองทางออก, หาจุดผิด |
| 🤖 AI & API | 6 (4, 23–27) | AI ร่างคำตอบ/ตรวจข้อมูล, HTTP POST, เติมช่องว่าง, ทายผล AI + IF |
| 🏪 เคสธุรกิจจริง | 5 (28, 6, 29, 30, 5) | คลินิก (จอง+เตือน), รีสอร์ท (3 สถานะชำระ), ร้านออนไลน์ (VIP), Sandbox |

- [x] ฟิลด์ `track`, `difficulty` (ดาว 1–3) ในทุกด่าน และตัวเลือกด่านแบ่งตามสายพร้อมแถบความคืบหน้า (ปลดล็อกแบบแนะนำ: 👉 ด่านถัดไป / 🔒 ควรทำก่อนหน้า แต่กดเข้าได้)
- [x] แยกเป็น `shared/levels/<สาย>.js` + `shared/levels.js` (รวม + TRACKS)
- [x] **สร้าง checks อัตโนมัติจากเฉลย** (`deriveChecks`) — ด่านใหม่เขียนแค่เฉลย + โจทย์ ไม่ต้องเขียน checks เอง (ตรวจครบ: บล็อก, สาย/พอร์ต, ตัวแปรในช่อง, operator/ค่าเทียบ, ชีตไม่ซ้ำ + กฎ reachable/upstreamVars) เพิ่มข้อตรวจเองด้วย `extraChecks`
- [x] คำใบ้สร้างอัตโนมัติจากข้อตรวจเมื่อด่านไม่ได้เขียน `hint` เอง
- [x] ชุดทดสอบ `tests/levels.test.js` (106 ข้อ): โครงสร้างทุกด่าน, เฉลยผ่าน, โจทย์เริ่มต้น/กระดานเปล่าไม่ผ่าน, เฉลยรันจำลองแล้วไม่มีคำเตือนในทุกชุดข้อมูลตัวอย่าง
- [ ] `requires` แบบบังคับล็อก (ตอนนี้ล็อกแบบแนะนำเท่านั้น)
- [ ] เพิ่มด่านเคสธุรกิจให้มากกว่านี้ (ร้านอาหาร ฯลฯ) และด่านจากคอลเลกชัน n8n (ถ้าเลือกทาง A: ตัวแปลง + คัดมือ)
- [ ] เนื้อหาด่านใหม่ (id 9–30) ยังไม่ผ่านการลองเล่นโดยผู้เรียนจริง — ตรวจด้วยเครื่องแล้วเท่านั้น ควรให้คนลองเล่นแล้วปรับคำใบ้/ความยาก

- [x] **สร้างด่านเอง**: ออกแบบ flow → "ตั้งเป็นเฉลย" → เขียนโจทย์/คำใบ้ → สร้าง `checks` อัตโนมัติจาก flow → export เป็นไฟล์ด่านให้คนอื่นเล่น
- [x] **ความปลอดภัยของไฟล์ด่านที่นำเข้า** (`shared/sanitize.js` + `tests/sanitize.test.js`): ไฟล์ด่านแชร์ข้ามคนได้ จึงเป็นข้อมูลไม่น่าเชื่อถือ — ก่อนแก้ พบว่าฟิลด์ `badge`, `hint`, `hints` ของด่านที่นำเข้าถูกใส่ลง `innerHTML` และรันสคริปต์ได้ (XSS) ตอนนี้ทุกเส้นทางบันทึก/อ่านผ่านตัวทำความสะอาด: ตัดอักขระเปิดแท็ก/ปิด attribute, จำกัดความยาว, ตรวจชนิดบล็อก/พอร์ต/id, ออก id ใหม่ตอนนำเข้า (กันทับด่านระบบ), เก็บเฉพาะ checks ที่ checker รู้จัก
- [ ] นำเข้า Flow ใน Studio (`applyImportedFlow`) ยังไม่ผ่านตัวตรวจแบบเดียวกัน (ปลอดภัยต่อ XSS เพราะแสดงผลผ่าน escapeHtml แต่ไฟล์ที่โครงสร้างผิดอาจทำให้กระดานพังได้)
- [ ] ปุ่ม "ดูเฉลย" ปลดล็อกตามจำนวนครั้งส่งตรวจที่เก็บในหน่วยความจำ — โหลดหน้าใหม่แล้วล็อกอีก (ยกเว้นด่านที่ผ่านแล้ว)

## Phase 5 — Backend (ทางเลือก)

ทำเมื่อต้องการผู้ใช้หลายคน หรือใช้สอนเป็นห้องเรียน

**5a — AI ด้วย Google Antigravity SDK** (backend Python ใน `backend/`)
- [x] AI Coach: `POST /coach` ให้คำใบ้จาก flow + ผลตรวจ (ปุ่มในหน้าผลตรวจ, fallback เมื่อไม่มี backend/key)
- [x] agent จำกัดสิทธิ์: มี tool `finish` อย่างเดียว, จำกัด token, ตรวจขนาดอินพุต
- [x] **ใช้ API key (Thirx, เข้ากันได้กับ OpenAI) เป็นเส้นทางหลัก** — ตั้ง `THIRX_API_KEY` ใน `.env`; ทดสอบกับของจริงแล้ว (ตอบภายใน ~12–17 วินาที, ผ่านหน้าเว็บครบทาง); เส้นทาง Google Login (Vertex AI / ADC) เก็บเป็นทางเลือกสำรอง (ยังไม่เคยทดสอบกับ Gemini จริง — ต้องผูก billing ก่อน)
- [x] Antigravity SDK ไม่รองรับ API key ของ OpenAI-compatible (โหมด `LocalOpenAIAgentConfig` ออกแบบไว้สำหรับเซิร์ฟเวอร์ในเครื่องอย่าง Ollama) จึงเรียก Thirx ด้วย `httpx` ตรงๆ แทน; SDK ใช้เฉพาะเส้นทาง Vertex
- [ ] คุณภาพคำใบ้จากโมเดลฟรี (Qwen3.8-27B-free) ยังไม่ได้ประเมินเป็นระบบ — ลองแล้ว 2 ตัวอย่างได้คำใบ้ตรงกับผลตรวจ แต่ควรให้คนลองกับหลายด่านและดูว่าเผลอเฉลยเกินระดับหรือไม่
- [ ] AI รีวิว flow ในโหมด Studio (วิจารณ์ดีไซน์ที่กฎตรวจไม่เจอ)
- [ ] AI ช่วยสร้างด่านจากคำอธิบายภาษาไทย (structured output → flow เฉลย + checks + คำใบ้) — ช่วยเร่ง Phase 3
- [ ] บล็อก AI ในตัวจำลองเรียก LLM จริง (ตอนนี้เป็นกฎคำสำคัญ)
- [ ] พิมพ์ภาษาไทยแล้วให้ AI วางบล็อกบนกระดาน

**5b — ข้อมูลและผู้ใช้ (Node.js + SQLite Backend)** ✅
- [x] เลือกเทคโนโลยี: Node.js (Built-in `node:sqlite` + `node:http`, Zero external dependencies)
- [x] API ตามเมธอดของ `LocalApi`: `getLevels`, `loadFlow`, `saveFlow`, `checkLevel`, `getProgress`
- [x] ตรวจคำตอบฝั่ง server ด้วย `shared/checker.js` ตัวเดียวกัน (API ซ่อน `template` เฉลยจากผู้เรียน)
  - ⚠️ **ข้อจำกัด: ยังไม่ได้ซ่อนเฉลยจริง** — หน้าเว็บยังโหลด `shared/levels/*.js` (ซึ่งมีเฉลยทั้ง 30 ด่าน) เป็นไฟล์ static ผู้เรียนเปิด DevTools ดูได้เสมอ การซ่อนที่ API จึงมีผลแค่ด่านสร้างเอง ถ้าต้องการซ่อนจริง ต้องแยกเฉลย/`checks` ออกจากไฟล์ที่เบราว์เซอร์โหลด (ให้มีเฉพาะ server) แล้วหน้าเว็บดึงโจทย์จาก API เท่านั้น
- [x] บัญชีผู้ใช้ + ความคืบหน้าข้ามเครื่อง (ตาราง `users`, `sessions`, `progress`, `flows`)
- [x] แชร์ด่าน/Flow ที่สร้างใน Studio ผ่านลิงก์ (`POST /api/share` และ `?share=<code>`)
- [x] หน้าดูคะแนนรวมสำหรับผู้สอน (Teacher Classroom Dashboard: สรุปภาพรวมและสถิติรายบุคคล)
- [x] สลับ `const Api = RemoteApi` อัตโนมัติด้วย Dynamic Proxy ใน `frontend/js/api/storage.js` พร้อมปุ่มซิงค์ Local ขึ้น Server

**5b — การเสริมความปลอดภัย (ตรวจพบหลัง agent ส่งงานรอบแรก และแก้แล้ว; ทดสอบใน `tests/phase5b_security.test.js`)**
- [x] **สมัครเป็นผู้สอนเองไม่ได้อีกต่อไป** — ก่อนแก้ ใครก็ส่ง `role: "teacher"` ตอนสมัครแล้วเห็นข้อมูลนักเรียนทั้งห้องได้; ตอนนี้สมัครเองได้เฉพาะนักเรียน ผู้สอนต้องใส่รหัส `TEACHER_SIGNUP_CODE` (ตั้งฝั่ง server; ไม่ตั้ง = สมัครผู้สอนเองไม่ได้)
- [x] **ปฏิเสธ Origin นอกรายการ** (ค่าเริ่มต้นเฉพาะ `http://localhost:5173` / `http://127.0.0.1:5173`, เพิ่มด้วย `ALLOWED_ORIGINS`) แทน CORS `*` และบังคับ `Content-Type: application/json` — ก่อนแก้ เว็บใดๆ ที่ผู้ใช้เปิดอยู่เรียก API บน localhost ได้ (ลบ/เขียนทับด่าน, เผาโควตา AI); ใช้กับ Python backend (`/coach`) ด้วย
- [x] ด่านสร้างเอง/แชร์/AI Coach ต้องล็อกอิน, เขียนทับ/ลบได้เฉพาะเจ้าของหรือผู้สอน, เฉลยของด่านสร้างเองเห็นได้เฉพาะเจ้าของ/ผู้สอน, ข้อมูลแชร์ผ่านตัวทำความสะอาดก่อนเก็บและก่อนใช้, จำกัด AI Coach 10 ครั้ง/นาที/คน
- [x] จำกัดล็อกอินผิด 10 ครั้ง/15 นาที (429), เทียบรหัสผ่านแบบ timing-safe, เก็บ session token เป็นแฮช SHA-256 (ไม่เก็บค่าดิบ — session เก่าในฐานข้อมูลเดิมจะใช้ไม่ได้ ต้องล็อกอินใหม่), error 500 ไม่ส่งข้อความภายในออกไป, body ใหญ่เกินตัดการเชื่อมต่อ

### เป้าหมายและเหตุผล
ทำให้เล่นด่านและออกแบบ flow ได้จริงบนมือถือ (จอแคบ ~360–430px, แท็บเล็ตแนวตั้ง) โดย **แยกหน้าตาเป็น `frontend/mobile.html`** ไม่ยุ่งกับ `index.html` ของ desktop แต่ **ใช้ตรรกะร่วมกัน** (`shared/`, `frontend/js/engine/`, `frontend/js/api/`) เพื่อไม่ต้องแก้ซ้ำสองที่

ปัญหาที่พบตอนตรวจ (ที่ 375px) ซึ่งเป็นเหตุผลที่ต้องแยก:
- **นิ้วสัมผัสยังใช้ไม่ได้เลย** — การลากบล็อก/ต่อสาย/เลื่อนกระดานเขียนด้วย mouse events ทั้งหมด:
  - `frontend/index.html:195-197` — `onmousedown/onmousemove/onmouseup` บน `#workspace-viewport` (เลื่อนกระดาน, ลากบล็อก, ลากสาย)
  - `frontend/js/engine/canvas.js:30,80,106` — `onmousedown` บนบล็อก, พอร์ตขาเข้า (`onInputPortClick`), พอร์ตขาออก (`onOutputPortMouseDown`)
  - `frontend/js/engine/palette.js:31-32` + `index.html:228-229` — คลังบล็อกใช้ HTML5 drag-and-drop (`draggable`, `ondragstart`, `ondragover`, `ondrop`) ซึ่งมือถือส่วนใหญ่ไม่รองรับ
- แถบด้านบนเบียดกัน ข้อความปุ่มตัดบรรทัด; เปิดแผงโจทย์แล้ว **มองไม่เห็นกระดาน**; มี `@media` จุดเดียว (`frontend/css/app.css:118`, ที่ 768px)
- โค้ดผูกกับ id ขององค์ประกอบกว่า 140 จุด (`getElementById`) — หน้าใหม่ต้องมี id ชุดเดียวกันในส่วนที่ engine เรียกใช้

### ข้อห้าม / เงื่อนไขที่ต้องรักษา (สำคัญ)
1. **พฤติกรรมของหน้า desktop (`index.html`) ต้องไม่เปลี่ยน** — เมาส์ลาก/ต่อสาย/เลื่อน/ซูมทำงานเหมือนเดิมทุกอย่าง
2. ไม่ลอกตรรกะไปสร้างซ้ำในไฟล์ mobile — ถ้าต้องแก้ engine ให้แก้ที่ไฟล์ร่วมใน `frontend/js/engine/` แล้วให้ทั้งสองหน้าใช้
3. สคริปต์ทั้งหมดเป็น classic `<script>` (ไม่ใช่ ES modules) และฟังก์ชันเป็น global — หน้า mobile ต้องโหลดตามลำดับเดียวกับ `index.html` (ดูท้ายไฟล์ `index.html`) เพื่อให้เปิดจาก `file://` ได้
4. ข้อมูลจากผู้ใช้/ไฟล์ด่านที่ใส่ลง `innerHTML` ต้อง escape (`escapeHtml`) หรือผ่าน `shared/sanitize.js` เสมอ — เคยมีช่องโหว่ XSS มาแล้ว ห้ามเพิ่มจุดใหม่
5. อย่า commit `.env`, `test_thirx.py` หรือคีย์ใดๆ

## หลักการที่ใช้ตลอดโปรเจกต์

- ข้อมูลและตรรกะอยู่ใน `shared/` (pure function, ไม่แตะ DOM) เพื่อใช้ซ้ำได้ทั้งเบราว์เซอร์และ backend
- UI เรียกข้อมูลผ่าน `Api` เท่านั้น ไม่เรียก `localStorage` ตรงๆ
- ด่านใหม่ทุกด่านต้องมี `checks` และเฉลย (`template`) ที่ผ่านการตรวจ
