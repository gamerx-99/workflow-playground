# Roadmap — Workflow Automation Lab

> อัปเดตล่าสุด: 2026-10-21

เป้าหมาย: พัฒนาจากแบบฝึกหัด 5 ด่าน ให้เป็นแอปที่เป็นทั้ง **ที่ฝึก** และ **ที่ออกแบบ** ระบบ Automation ในตัว มีโจทย์หลายรูปแบบ มีแบบทดสอบจำนวนมาก และหน้าใช้งานที่ดี

| เฟส | หัวข้อ | สถานะ |
|---|---|---|
| 1 | วางฐาน: แยกโค้ด + ระบบตรวจคำตอบ | ✅ เสร็จแล้ว |
| 2 | หลายรูปแบบ + จำลองการทำงาน (Run) | 🟡 ทำแล้วส่วนใหญ่ (เหลือโหมด order) |
| 3 | เพิ่มแบบทดสอบเป็น 30 ด่าน | ✅ เสร็จแล้ว (30 ด่าน 5 สาย) |
| 4 | UI ใหม่ + โหมดฝึก / ออกแบบ (Studio) | ⬜ |
| 5 | Backend (ทางเลือก) | ⬜ |

---

## Phase 1 — วางฐาน ✅

- [x] แยกโค้ดออกเป็น `shared/` (ข้อมูล + ตรรกะ) และ `frontend/` (หน้าเว็บ)
- [x] ย้าย `BLOCK_CATALOG` / `LEVELS` / `VARIABLE_DICTIONARY` ออกเป็นไฟล์ข้อมูล
- [x] ชั้น `Api` (`frontend/js/api/storage.js`) ใช้ `localStorage` — สลับเป็น backend ได้ภายหลังโดยไม่ต้องแก้ UI
- [x] ระบบตรวจคำตอบ `checkFlow()` (`shared/checker.js`) ชนิด check: `block`, `link`, `vars`, `value`, `distinct`, `minBlocks`, `reachable`, `upstreamVars`
- [x] ใส่ `checks` ให้ด่าน 1–5 และปุ่ม "✅ ส่งตรวจด่านนี้" แสดงผลรายข้อ
- [x] บันทึกด่านที่ผ่านแล้ว (✅ บนแท็บด่าน)
- [x] ลบไฟล์เดิม `workflow-playground.html`

**ค้างจากเฟสนี้**
- [ ] ทดสอบเปิด `frontend/index.html` แบบดับเบิลคลิก (`file://`) — ทดสอบแล้วเฉพาะผ่าน localhost
- [x] เริ่มใช้ git + ขึ้น GitHub แล้ว

## Phase 2 — หลายรูปแบบ (ข้อ 1)

**รูปแบบโจทย์** — เพิ่มฟิลด์ `mode` ใน level
- [x] `build` — ต่อ flow เองตั้งแต่ต้น (ด่าน 1–4)
- [x] `fill` — flow ต่อไว้แล้ว ให้เติมตัวแปรในช่องที่เว้นไว้ (ด่าน 6)
- [x] `debug` — flow ต่อไว้ผิด ให้หาจุดผิดและแก้ (ด่าน 7)
- [ ] `order` — มีบล็อกให้ครบ ให้ต่อสายเรียงลำดับให้ถูก
- [x] `predict` — ดู flow + ข้อมูลตัวอย่าง แล้วทายผลลัพธ์ปลายทาง (ด่าน 8) — เฉลยคำนวณจากตัวจำลอง
- [x] `sandbox` — อิสระ ตรวจเฉพาะกฎทั่วไป (ด่าน 5)

**จำลองการทำงาน (▶ Run)**
- [x] ใส่ข้อมูลตัวอย่าง (sample payload) ให้ Trigger แต่ละชนิด (เลือกชุดข้อมูลได้)
- [x] ไล่รันตามเส้นเชื่อม แทนค่า `{{ตัวแปร}}` จริง และเลือกสาย IF/Switch/Loop ตามเงื่อนไข
- [x] แสดงค่าตัวแปรที่ไหลผ่านแต่ละบล็อก + ไฮไลต์ลำดับบนบล็อก/เส้นเชื่อมบนกระดาน
- [x] วางตรรกะจำลองไว้ใน `shared/simulator.js` (ไม่แตะ DOM) + ชุดทดสอบ `tests/levels.test.js` (รัน `node tests/levels.test.js`)
- [ ] AI ในตัวจำลองเป็นกฎง่ายๆ (คำว่า ด่วน/ช่วยด้วย ฯลฯ) ไม่ได้เรียก LLM จริง

**รวมเครื่องมือ**
- ~~รวม Network Topology / BOQ~~ — ตัดออก: แยกไปเป็นโปรเจกต์ใหม่แล้ว (คนละแนวทางกับ Workflow Automation)
- [ ] ยังคงแยก engine กระดาน (วางบล็อก ลากสาย ซูม) ให้ใช้ซ้ำได้ เผื่อโปรเจกต์อื่นหยิบไปใช้

## Phase 3 — แบบทดสอบมากขึ้น (ข้อ 2)

30 ด่าน แบ่งเป็น 5 สาย (track) — ไฟล์ด่านอยู่ใน `shared/levels/`

| สาย | ด่าน (id) | เนื้อหา |
|---|---|---|
| 🧱 พื้นฐานตัวแปร | 6 (1, 9–13) | Trigger → Action, ตัวแปรจากบล็อกกลางทาง ({{event_link}}, {{row_number}}), เติมช่องว่าง |
| 🔀 เงื่อนไข | 7 (2, 14–17, 7, 8) | IF, Contains, Switch 3 สาย, หาจุดผิด, ทายผล |
| 📊 ข้อมูล & Loop | 6 (3, 18–22) | Loop, Formatter, Sheets read, HTTP GET, Loop สองทางออก, หาจุดผิด |
| 🤖 AI & API | 6 (4, 23–27) | AI ร่างคำตอบ/ตรวจข้อมูล, HTTP POST, เติมช่องว่าง, ทายผล AI + IF |
| 🏪 เคสธุรกิจจริง | 5 (28, 6, 29, 30, 5) | คลินิก (จอง+เตือน), รีสอร์ท (3 สถานะชำระ), ร้านออนไลน์ (VIP), Sandbox |

- [x] ฟิลด์ `track`, `difficulty` (ดาว 1–3) ในทุกด่าน และตัวเลือกด่านแบ่งตามสายพร้อมแถบความคืบหน้า (ปลดล็อกแบบแนะนำ: 👉 ด่านถัดไป / 🔒 ควรทำก่อนหน้า แต่กดเข้าได้)
- [x] แยกเป็น `shared/levels/<สาย>.js` + `shared/levels.js` (รวม + TRACKS)
- [x] **สร้าง checks อัตโนมัติจากเฉลย** (`deriveChecks`) — ด่านใหม่เขียนแค่เฉลย + โจทย์ ไม่ต้องเขียน checks เอง (ตรวจครบ: บล็อก, สาย/พอร์ต, ตัวแปรในช่อง, operator/ค่าเทียบ, ชีตไม่ซ้ำ + กฎ reachable/upstreamVars) เพิ่มข้อตรวจเองด้วย `extraChecks`
- [x] คำใบ้สร้างอัตโนมัติจากข้อตรวจเมื่อด่านไม่ได้เขียน `hint` เอง
- [x] ชุดทดสอบ `tests/levels.test.js` (106 ข้อ): โครงสร้างทุกด่าน, เฉลยผ่าน, โจทย์เริ่มต้น/กระดานเปล่าไม่ผ่าน, เฉลยรันจำลองแล้วไม่มีคำเตือนในทุกชุดข้อมูลตัวอย่าง
- [ ] `requires` แบบบังคับล็อก (ตอนนี้ล็อกแบบแนะนำเท่านั้น)
- [ ] เพิ่มด่านเคสธุรกิจให้มากกว่านี้ (ร้านอาหาร ฯลฯ) และด่านจากคอลเลกชัน n8n (ถ้าเลือกทาง A: ตัวแปลง + คัดมือ)
- [ ] เนื้อหาด่านใหม่ (id 9–30) ยังไม่ผ่านการลองเล่นโดยผู้เรียนจริง — ตรวจด้วยเครื่องแล้วเท่านั้น ควรให้คนลองเล่นแล้วปรับคำใบ้/ความยาก

## Phase 4 — UI + โหมดฝึก / ออกแบบ (ข้อ 3, 4)

**หน้าใช้งาน**
- [ ] หน้าแรก: การ์ดแต่ละสาย + แถบความคืบหน้า + ปุ่ม "เล่นต่อ"
- [ ] หน้าทำด่าน: โจทย์แผงซ้าย, ผลตรวจแผงขวา, คำใบ้เปิดทีละขั้น
- [ ] ทัวร์แนะนำการใช้งานครั้งแรก
- [ ] รองรับจอแคบ / แท็บเล็ต (ตอนนี้แถบด้านบนเบียดกัน)

**โหมดฝึก (Practice)**
- [ ] ทำด่าน → ส่งตรวจ → ดูเฉลย (ปลดหลังพยายามแล้ว)

**โหมดออกแบบ (Studio)**
- [ ] กระดานเปล่า บันทึกได้หลายโปรเจกต์
- [ ] Import / Export เป็น JSON
- [ ] **สร้างด่านเอง**: ออกแบบ flow → "ตั้งเป็นเฉลย" → เขียนโจทย์/คำใบ้ → สร้าง `checks` อัตโนมัติจาก flow → export เป็นไฟล์ด่านให้คนอื่นเล่น

## Phase 5 — Backend (ทางเลือก)

ทำเมื่อต้องการผู้ใช้หลายคน หรือใช้สอนเป็นห้องเรียน

**5a — AI ด้วย Google Antigravity SDK** (backend Python ใน `backend/`)
- [x] AI Coach: `POST /coach` ให้คำใบ้จาก flow + ผลตรวจ (ปุ่มในหน้าผลตรวจ, fallback เมื่อไม่มี backend/key)
- [x] agent จำกัดสิทธิ์: มี tool `finish` อย่างเดียว, จำกัด token, ตรวจขนาดอินพุต
- [x] **ใช้ API key (Thirx, เข้ากันได้กับ OpenAI) เป็นเส้นทางหลัก** — ตั้ง `THIRX_API_KEY` ใน `.env`; ทดสอบกับของจริงแล้ว (ตอบภายใน ~12–17 วินาที, ผ่านหน้าเว็บครบทาง); เส้นทาง Google Login (Vertex AI / ADC) เก็บเป็นทางเลือกสำรอง (ยังไม่เคยทดสอบกับ Gemini จริง — ต้องผูก billing ก่อน)
- [x] Antigravity SDK ไม่รองรับ API key ของ OpenAI-compatible (โหมด `LocalOpenAIAgentConfig` ออกแบบไว้สำหรับเซิร์ฟเวอร์ในเครื่องอย่าง Ollama) จึงเรียก Thirx ด้วย `httpx` ตรงๆ แทน; SDK ใช้เฉพาะเส้นทาง Vertex
- [ ] คุณภาพคำใบ้จากโมเดลฟรี (Qwen3.8-27B-free) ยังไม่ได้ประเมินเป็นระบบ — ลองแล้ว 2 ตัวอย่างได้คำใบ้ตรงกับผลตรวจ แต่ควรให้คนลองกับหลายด่านและดูว่าเผลอเฉลยเกินระดับหรือไม่
- [ ] AI รีวิว flow ในโหมด Studio (วิจารณ์ดีไซน์ที่กฎตรวจไม่เจอ)
- [ ] AI ช่วยสร้างด่านจากคำอธิบายภาษาไทย (structured output → flow เฉลย + checks + คำใบ้) — ช่วยเร่ง Phase 3
- [ ] บล็อก AI ในตัวจำลองเรียก LLM จริง (ตอนนี้เป็นกฎคำสำคัญ)
- [ ] พิมพ์ภาษาไทยแล้วให้ AI วางบล็อกบนกระดาน

**5b — ข้อมูลและผู้ใช้**
- [ ] เลือกเทคโนโลยี: Supabase (Postgres + Auth + Edge Functions) หรือ Node (Hono/Express) + SQLite
- [ ] API ตามเมธอดของ `LocalApi`: `getLevels`, `loadFlow`, `saveFlow`, `checkLevel`, `getProgress`
- [ ] ตรวจคำตอบฝั่ง server ด้วย `shared/checker.js` ตัวเดียวกัน (ซ่อนเฉลยจากผู้เรียน)
- [ ] บัญชีผู้ใช้ + ความคืบหน้าข้ามเครื่อง
- [ ] แชร์ด่านที่สร้างใน Studio ผ่านลิงก์
- [ ] หน้าดูคะแนนรวมสำหรับผู้สอน
- [ ] สลับ `const Api = RemoteApi` ใน `frontend/js/api/storage.js`

## หลักการที่ใช้ตลอดโปรเจกต์

- ข้อมูลและตรรกะอยู่ใน `shared/` (pure function, ไม่แตะ DOM) เพื่อใช้ซ้ำได้ทั้งเบราว์เซอร์และ backend
- UI เรียกข้อมูลผ่าน `Api` เท่านั้น ไม่เรียก `localStorage` ตรงๆ
- ด่านใหม่ทุกด่านต้องมี `checks` และเฉลย (`template`) ที่ผ่านการตรวจ
