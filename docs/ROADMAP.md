# Roadmap — Workflow Automation Lab

> อัปเดตล่าสุด: 2026-10-21

เป้าหมาย: พัฒนาจากแบบฝึกหัด 5 ด่าน ให้เป็นแอปที่เป็นทั้ง **ที่ฝึก** และ **ที่ออกแบบ** ระบบ Automation ในตัว มีโจทย์หลายรูปแบบ มีแบบทดสอบจำนวนมาก และหน้าใช้งานที่ดี

## Phase 6 — รองรับมือถือ (หน้าแยก) ⬜

> สถานะ: วางแผนแล้ว ยังไม่เริ่มเขียน (มอบหมายให้ agent อื่นทำต่อได้ — ส่วนนี้เขียนให้อ่านจบแล้วลงมือได้เลย)

### เป้าหมายและเหตุผล
ทำให้เล่นด่านและออกแบบ flow ได้จริงบนมือถือ (จอแคบ ~360–430px, แท็บเล็ตแนวตั้ง) โดย **แยกหน้าตาเป็น `frontend/mobile.html`** ไม่ยุ่งกับ `index.html` ของ desktop แต่ **ใช้ตรรกะร่วมกัน** (`shared/`, `frontend/js/engine/`, `frontend/js/api/`) เพื่อไม่ต้องแก้ซ้ำสองที่

ปัญหาที่พบตอนตรวจ (ที่ 375px) ซึ่งเป็นเหตุผลที่ต้องแยก:
- **นิ้วสัมผัสยังใช้ไม่ได้เลย** — การลากบล็อก/ต่อสาย/เลื่อนกระดานเขียนด้วย mouse events ทั้งหมด:
  - `frontend/index.html:195-197` — `onmousedown/onmousemove/onmouseup` บน `#workspace-viewport` (เลื่อนกระดาน, ลากบล็อก, ลากสาย)
  - `frontend/js/engine/canvas.js:30,80,106` — `onmousedown` บนบล็อก, พอร์ตขาเข้า (`onInputPortClick`), พอร์ตขาออก (`onOutputPortMouseDown`)
  - `frontend/js/engine/palette.js:31-32` + `index.html:228-229` — คลังบล็อกใช้ HTML5 drag-and-drop (`draggable`, `ondragstart`, `ondragover`, `ondrop`) ซึ่งมือถือส่วนใหญ่ไม่รองรับ
- แถบด้านบนเบียดกัน ข้อความปุ่มตัดบรรทัด; เปิดแผงโจทย์แล้ว **มองไม่เห็นกระดาน**; มี `@media` จุดเดียว (`frontend/css/app.css:118`, ที่ 768px)
- โค้ดผูกกับ id ขององค์ประกอบกว่า 140 จุด (`getElementById`) — หน้าใหม่ต้องมี id ชุดเดียวกันในส่วนที่ engine เรียกใช้

### ข้อห้าม / เงื่อนไขที่ต้องรักษา (สำคัญ)
1. **พฤติกรรมของหน้า desktop (`index.html`) ต้องไม่เปลี่ยน** — เมาส์ลาก/ต่อสาย/เลื่อน/ซูมทำงานเหมือนเดิมทุกอย่าง
2. ไม่ลอกตรรกะไปสร้างซ้ำในไฟล์ mobile — ถ้าต้องแก้ engine ให้แก้ที่ไฟล์ร่วมใน `frontend/js/engine/` แล้วให้ทั้งสองหน้าใช้
3. สคริปต์ทั้งหมดเป็น classic `<script>` (ไม่ใช่ ES modules) และฟังก์ชันเป็น global — หน้า mobile ต้องโหลดตามลำดับเดียวกับ `index.html` (ดูท้ายไฟล์ `index.html`) เพื่อให้เปิดจาก `file://` ได้
4. ข้อมูลจากผู้ใช้/ไฟล์ด่านที่ใส่ลง `innerHTML` ต้อง escape (`escapeHtml`) หรือผ่าน `shared/sanitize.js` เสมอ — เคยมีช่องโหว่ XSS มาแล้ว ห้ามเพิ่มจุดใหม่
5. อย่า commit `.env`, `test_thirx.py` หรือคีย์ใดๆ

### ขั้นที่ 1 — ให้ engine รับนิ้วสัมผัส (Pointer Events) โดย desktop ไม่เปลี่ยน
- [ ] เปลี่ยน mouse events เป็น **Pointer Events** (`pointerdown/pointermove/pointerup/pointercancel`) ที่ 3 ไฟล์ข้างต้น (เมาส์ นิ้ว ปากกา ใช้ชุดเดียวกัน) และเพิ่ม `touch-action: none` บนกระดาน/บล็อก/พอร์ต เพื่อไม่ให้เบราว์เซอร์แย่งท่าทางไปเลื่อนหน้า
- [ ] ใช้ `setPointerCapture` ตอนลากบล็อก/เลื่อนกระดาน เพื่อให้การลากต่อเนื่องแม้นิ้วออกนอกบล็อก
- [ ] **ต่อสายด้วยนิ้ว:** แตะพอร์ตขาออก → แตะพอร์ตขาเข้า (โหมดแตะสองครั้ง) นอกเหนือจากการลาก; พอร์ตต้องมีพื้นที่แตะอย่างน้อย 44×44px (ตอนนี้ `.port-dot` กว้าง 16px — ขยายพื้นที่แตะด้วย padding/pseudo-element ไม่ต้องขยายจุดที่มองเห็น)
- [ ] **เลื่อนกระดาน:** นิ้วเดียวลากบนพื้นว่าง; **ซูม:** pinch สองนิ้ว (ปรับ `canvasZoom` ในช่วง 0.5–1.5 เดิม โดยใช้ `changeZoom`/`applyZoom` ใน `engine/viewport.js` และรักษาจุดกึ่งกลางภาพ เหมือน `changeZoom` ปัจจุบัน)
- [ ] เพิ่มบล็อกด้วยการ **แตะเลือกจากรายการ** (ฟังก์ชัน `addNodeToCanvas(type)` ใช้ได้อยู่แล้ว — วางที่กลางจอ) ไม่ต้องพึ่ง drag-and-drop บนมือถือ
- [ ] ทดสอบ regression ของ desktop: เปิด `index.html` ที่ความกว้างปกติ แล้วลากบล็อก, ต่อสาย (ลาก + คลิก), เลื่อนกระดานด้วย Space+ลาก, ซูม, ลบสาย ให้ครบเหมือนก่อนแก้ — ถ้าเขียนเทสต์อัตโนมัติด้วยเบราว์เซอร์ได้ให้เก็บไว้ใน `tests/`

### ขั้นที่ 2 — สร้าง `frontend/mobile.html`
- [ ] ไฟล์ใหม่ `frontend/mobile.html` + `frontend/css/mobile.css` + `frontend/js/mobile/*.js` (ตัวควบคุมหน้าตาเฉพาะมือถือเท่านั้น)
- [ ] **โครงหน้าจอ: ทีละหน้า ไม่แสดงหลายแผงพร้อมกัน** ด้วย **แท็บล่าง** — 📋 โจทย์ / 🧩 กระดาน / ⚙️ ตั้งค่าบล็อก / ✅ ผลตรวจ (หน้าแรกกับ Studio เข้าจากเมนู ☰)
- [ ] กระดานเต็มจอ มีแถบเครื่องมือเล็กลอยอยู่ (ซูม, จัดกลาง, ▶ จำลอง, ส่งตรวจ, ปุ่มเพิ่มบล็อก ➕ เปิดรายการบล็อกแบบ bottom sheet)
- [ ] **หน้าต่างย่อยทั้งหมดเป็น bottom sheet** (เลื่อนขึ้นจากด้านล่าง): ผลตรวจ, ผลจำลอง (`run-modal`), ตัวเลือกด่าน (`level-picker-modal`), ทายผล (`predict-modal`), คำใบ้, ตัวช่วยสร้างด่าน — ใช้ id เดิมของ element ที่ engine/ui เรียกใช้ เพื่อไม่ต้องแก้ตรรกะ
- [ ] ปุ่มสลับ "ใช้หน้า desktop" กลับไป `index.html`
- [ ] ใช้ความสูงด้วย `100dvh` (เลี่ยงปัญหาแถบ address bar ของเบราว์เซอร์มือถือ) และเผื่อ safe-area (`env(safe-area-inset-bottom)`) สำหรับแท็บล่าง
- [ ] ตัวหนังสือใน input อย่างน้อย 16px (กัน iOS ซูมหน้าเองตอนโฟกัส)

### ขั้นที่ 3 — สลับอัตโนมัติ + ปรับแต่ง
- [ ] `index.html` ตรวจความกว้างจอ (< 768px หรือ pointer แบบ coarse) แล้วพาไป `mobile.html` ครั้งแรก; จำตัวเลือกที่ผู้ใช้กดสลับเองใน `localStorage` (ห่อ `try/catch`) เพื่อไม่ดีดกลับไปมา
- [ ] ข้อมูลร่วมกัน (ความคืบหน้า, ด่านสร้างเอง, โปรเจกต์ Studio) ใช้ `localStorage` คีย์เดิมผ่าน `Api` — สลับหน้าแล้วข้อมูลต้องอยู่ครบ
- [ ] ปรับทัวร์ (`ui/tour.js`) ให้มีชุดขั้นตอนสำหรับมือถือ
- [ ] อัปเดต `README.md` (วิธีเปิดหน้ามือถือ) และตาราง/สถานะในไฟล์นี้

### เกณฑ์ที่ถือว่าเสร็จ (Acceptance)
ทดสอบในเบราว์เซอร์จำลองขนาด **375×812** (เครื่องมือ `resize_window preset mobile`) และอย่างน้อยหนึ่งครั้งบนมือถือจริง:
1. เปิด `mobile.html` ไม่มีแถบเลื่อนแนวนอนของหน้า และไม่มี error ใน console
2. เล่นด่าน 9 ได้ตลอดทาง **ด้วยนิ้ว/การสัมผัสเท่านั้น**: เพิ่มบล็อก 2 ตัว → ต่อสาย → แก้ตัวแปรในแผงตั้งค่า → ส่งตรวจ → ผ่าน (แสดงเป็น ✅)
3. ▶ จำลองการทำงานและผลตรวจเปิดเป็น bottom sheet อ่านและปิดได้ ไม่ล้นจอ
4. ซูม/เลื่อนกระดานด้วยนิ้วลื่นและไม่ทำให้ทั้งหน้าเลื่อน
5. สลับ `mobile.html` ↔ `index.html` แล้วความคืบหน้า/โปรเจกต์ไม่หาย
6. **Regression:** เทสต์ชุดเดิมผ่านครบ และ `index.html` บน desktop ใช้เมาส์ได้เหมือนเดิม (ลาก, ต่อสาย, ซูม, เลื่อน, ลบ)

### วิธีรันและทดสอบ

# ชุดทดสอบ (ต้องผ่านทั้งหมดก่อนส่งงาน)
node tests/levels.test.js

node tests/sanitize.test.js
backend/.venv/Scripts/python.exe -m unittest discover -s backend -p "test_backend.py"

ข้อควรระวังตอนทดสอบ: เบราว์เซอร์จำไฟล์ JS เก่า — ต้อง Ctrl+F5 หลังแก้; `alert()`/`confirm()`/`prompt()` ที่โค้ดเรียกใช้จะบล็อกการทดสอบอัตโนมัติ (override เป็นฟังก์ชันว่างก่อนทดสอบ); อย่าลืมล้าง `localStorage` ของข้อมูลทดสอบ

### ความเสี่ยงที่ควรรู้
- ผมตรวจได้เฉพาะเบราว์เซอร์จำลอง ยังไม่เคยลองบนมือถือจริง — ความไวของการลาก, การแย่งท่าทางกับเบราว์เซอร์ (เช่น ปัดกลับของ iOS), คีย์บอร์ดบนจอที่บังช่องกรอก อาจต่างจากที่จำลอง
- การเปลี่ยนเป็น Pointer Events แตะโค้ดที่ desktop ใช้อยู่ — เสี่ยง regression ที่สุดของเฟสนี้ ให้ทำขั้นที่ 1 แยกเป็น commit ของตัวเองและทดสอบ desktop ให้ครบก่อนไปขั้นถัดไป
- หน้าต่างย่อยและโครงหน้า (id ที่ engine/ui อ้างถึง) มีมาก ถ้าลืมใส่ id ใดใน `mobile.html` ฟังก์ชันที่เรียก `getElementById` จะได้ `null` แล้วพัง — ตรวจรายการ id ที่ใช้จริงด้วย `grep getElementById frontend/js` ก่อนเขียนหน้า

## หลักการที่ใช้ตลอดโปรเจกต์

- ข้อมูลและตรรกะอยู่ใน `shared/` (pure function, ไม่แตะ DOM) เพื่อใช้ซ้ำได้ทั้งเบราว์เซอร์และ backend
- UI เรียกข้อมูลผ่าน `Api` เท่านั้น ไม่เรียก `localStorage` ตรงๆ
- ด่านใหม่ทุกด่านต้องมี `checks` และเฉลย (`template`) ที่ผ่านการตรวจ
